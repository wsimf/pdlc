The problem

Agents are brilliant for 40 minutes.
Then the wheels come off.

01

Context evaporates

The plan lived in the chat. The chat is gone. The next session re-derives everything from scratch — badly.

02

Drift goes unnoticed

Nothing independently checks the output against the requirement, so small deviations compound into a rewrite.

03

You are the bottleneck

Every few minutes it stops and asks. You become a full-time prompt operator instead of an engineer.

04

"Was this reviewed? Did tests pass? Who approved it?" Nobody can answer from a transcript.

The limit isn't model capability. It's that nothing outside the agent holds the state.

What it is

The tracker is the state machine.

Point PDLC at a one-line idea or an existing work item. It resolves the workflow that work type follows, drives it stage by stage, pauses at the gates that need a person, and records every transition as evidence on the work item itself — not in a side database, not in a transcript.

  • Data-driven lifecycle. The work item's type selects its workflow, and the workflow definition supplies the stages, gates, transitions and owners. A feature runs one pipeline, a bug or a spike runs its own — configured, not hard-coded.
  • Machine-checked, never inferred. Stage, gate, task identity, PR linkage and completion readiness come from the store — never from branch names, checkboxes or prose.
  • Evidence, not logs. Each transition appends a comment explaining why. The work-item body stays a clean statement of current intent.
  • Human gates are explicit. Approvals, decisions, skips and completion are always yours. Everything else runs unattended.
$ pdlc inspect 142  →  # Due Next: Implementation · task 3 of 7 · gate Pending

The CLI

The agent's whole interface is one command.

Ask what's next, get an answer, act. Same input, same output, every run — tested Python, not a prompt.

$ pdlc inspect 142 --- Status: Implementation Gate State: CI Pending Lifecycle: Delivery pullRequests: - number: 139 state: OPEN --- # Tasks #143 api: export endpoint complete #144 csv serialiser complete #145 reports screen action in flight #146 e2e coverage needs plan # Due Next Checks are still running on PR #139. Re-run when they settle. No human needed.

Nothing is inferred

Stage, gate, task identity, PR linkage and completion readiness are resolved in Python against the tracker. The agent never guesses state from prose, branch names, ticked checkboxes or recent files — because it never has to.

Context collapses to one block

Metadata, the full task tree, the linked-PR check rollup and any warnings arrive as compact markdown in a single call. No crawling issues, comments and git history to rebuild the picture — and no tokens burned doing it.

# Due Next is an instruction

The routing table is applied for the agent, not handed to it. It gets one line naming the skill, command or person that owns the next move. Ask what's next, get an answer, act.

The CLI does the doing

Branches, stacked PRs, opening and closing tasks, evidence comments, validation and gate transitions all happen script-side. The agent writes code and calls commands; the bookkeeping is never left to its judgement.

Why you care

Four reasons your agent
runs for hours, not minutes.

DURABLE STATE

The loop survives the session

Kill the terminal, lose the context window, hand it to a teammate's agent — pdlc inspect reconstitutes exactly where the work stands and what is due next. No handoff doc, no re-explaining.

SELF-CORRECTING

Review before the error compounds

A read-only reviewer sub-agent checks each artifact against the requirements before the gate opens. Drift is caught one stage after it happens, not one week.

BOUNDED WORK

Small enough to actually finish

Implementation is decomposed into dependency-ordered delivery tasks, each shipped as its own stacked PR. Every unit fits comfortably in one context window.

FEWER INTERRUPTS

You are paged, not polled

Routing, reviews, CI reconciliation and retries-with-backoff run unattended. You only appear for approvals, product decisions and completion.
